# Dependency security policy

Scopeproof treats the deployed Worker bundle, AWS CDK/runtime packages, and the signed macOS candidate as separate release boundaries. Pull requests and weekly CI runs block High and Critical advisories in the full and production npm graphs. Pull requests also run the SHA-pinned GitHub dependency-review action, block Moderate-or-higher newly introduced vulnerabilities, and reject newly introduced AGPL, GPL, or SSPL dependencies. CI retains separate CycloneDX SBOMs for the root Worker graph and `infra/aws/cdk` graph for 30 days; the production macOS candidate carries its own attested SBOM.

The SHA-pinned Trivy action scans tracked source for High/Critical secret and infrastructure-as-code findings before dependency installation. Generated build output and dependency directories are excluded; application and CloudFormation source are not. `.trivyignore.yaml` contains one path-scoped, expiring exception for Trivy 0.70's failure to resolve the `!Ref TrailLogKey` intrinsic even though the template and contract tests bind that retained rotating customer-managed key to both CloudTrail and its Object-Locked S3 bucket. Any exception renewal requires security-owner review and fresh local scanner evidence.

This release SBOM is distinct from the operator-facing repository SBOM workspace. Keep the two artifacts separately labeled and retained:

| Artifact | Boundary | Trigger and retention | Assurance |
| --- | --- | --- | --- |
| Scopeproof Worker SBOM | Root locked npm graph | Security CI; retained with the exact commit | Describes the dependencies used to build the hosted Worker. |
| Scopeproof AWS SBOM | `infra/aws/cdk` locked pnpm graph | Security CI; retained with the exact commit | Describes CDK tooling and the JavaScript packages bundled into AWS Lambdas. |
| Scopeproof macOS candidate SBOM | Signed ZIP/DMG and native package dependency boundary | Protected production-candidate workflow; attested with provenance and a redacted notary receipt | Binds the exact production candidate without exposing Apple credentials or raw notarization output. |
| Repository evidence SBOM | A selected repository/commit from managed organization access or one exact, assessment-scoped one-time GitHub URL | Generated by an operator, encrypted as assessment evidence, independently approved, and retained under evidence policy | Describes pinned components parsed from supported lockfiles at the recorded commit. |

None of these artifacts is a vulnerability report or proof of deployment. Pair release SBOMs with build provenance and vulnerability scanning; pair repository evidence SBOMs with deployment attestations, scan results, and change-management records. See the [repository SBOM guide](SBOM_GUIDE.md).

## Temporary advisory exceptions

These exceptions apply only to local development/build tooling. They are not present in `npm audit --omit=dev`, are not imported by the deployed Worker, and do not permit externally reachable development servers.

| Dependency path | Severity | Rationale and compensating controls | Owner | Review by |
| --- | --- | --- | --- | --- |
| `drizzle-kit` → `@esbuild-kit/*` → `esbuild` | Moderate | The advisory affects the esbuild development server. Scopeproof uses this path only for local migration generation; CI installs with scripts disabled and never exposes a development server. Re-evaluate when Drizzle publishes a compatible fixed dependency path. | Platform Security | 2026-09-11 |
| `eslint-plugin-react-hooks` → `@babel/core` | Low | The advisory requires attacker-controlled source-map input during local analysis. Exceptions expire on the listed date. A pull request must update the dependency or explicitly renew the entry with current evidence; silent or permanent acceptance is not allowed.

## Release verification

Before release:

1. Run the full test/build suite and the pinned Trivy secret/IaC gate; require zero unsuppressed High/Critical findings.
2. Run `npm audit --audit-level=high`.
3. Run `npm audit --omit=dev --audit-level=high` and require zero production findings.
4. Generate and retain both root and AWS CDK CycloneDX SBOMs; for macOS, retain the candidate SBOM, provenance, receipt, checksums, and GitHub attestations as one release set.
5. Review any override or local replacement package as first-party security-sensitive code.
6. Retain each release SBOM with its exact commit, lockfile, build attestation, artifact digest, and deployed version so it cannot be confused with an assessment-generated repository SBOM.

Dependabot covers the root npm graph, `infra/aws/cdk`, and GitHub Actions. Action
references remain full immutable commit SHAs even when Dependabot proposes an
upgrade. The dependency-review license deny list is a minimum acquisition gate,
not a substitute for counsel or a complete license inventory; review unknown,
custom, dual-licensed, and file dependencies manually before release.
