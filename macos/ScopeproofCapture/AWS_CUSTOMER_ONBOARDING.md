# Native AWS customer onboarding

The Capture menu → AWS Customer Workspace opens a real native flow: PKCE browser sign-in (or refresh), membership and token challenge validation, protected per-customer/per-user P-256 device-key possession proof, enrollment, paged active-assessment selection, and scoped control/system selection. Sign-out removes the refresh credential without deleting device identity or evidence. Access and ID tokens are not persisted; ID-token claims are not used for authorization.

Release configuration is intentionally empty by default. Before signing the app, the release owner supplies `ScopeproofAWSHostedTenants` as an array of dictionaries in `Resources/Info.plist`. Each requires `tenantId`, `displayName`, `apiOrigin`, `issuer`, `authorizationEndpoint`, `tokenEndpoint`, and `clientId`. The HTTPS API origin must also be present in the existing `ScopeproofHostedAPIOrigins` allowlist. These are public routing values, never secrets. Register `scopeproof-capture://oauth/callback` in the Cognito public client. Do not add a client secret. The code does not accept a user-pasted token, device ID, key fingerprint, or arbitrary API origin.

Requires current `/v1/collector/me` with server-verified `uploadProofChallenge`, `/v1/customer/devices/enroll`, and `/v1/customer/collector-assessments/search`. Missing challenge, stale membership, revoked key, or out-of-scope choices fail closed. Enrollment proves key possession; no hardware-attestation claim is made.

Selection prepares local capture defaults and preserves a typed customer/assessment revision/catalog binding. It disables legacy automatic hosted upload. Submit / Check Capture revalidates current assessment scope, signs an enrolled-device upload manifest, requests an upload capability, sends the exact PNG, and reads server processing/review status. There is no client finalize endpoint: S3 ingestion, validation/scanning, and reconciliation are asynchronous. A successful PUT is never labeled validated or approved. The native client requests `scopeproof/evidence.collect` in addition to OpenID scopes.

Local EV IDs and signed manifests are never regenerated. A stable separate `evd_` resource ID is mapped to the exact local manifest hash in device-only Keychain, together with a durable device sequence and upload transaction journal. Presigned URLs are capabilities and never appear in sidecars, UI status, or logs. Ambiguous PUTs are status-checked, not silently retried into extra object versions. Expired ambiguous grants and stuck quarantine records require administrator reconciliation; this is intentionally not a claim of autonomous recovery.

Optionally supply `portalOrigin` from the deployment's exact `webOrigin` output. It is independent from `apiOrigin` and must be HTTPS with no path, query, or credentials. The client never derives a web origin by stripping an API hostname prefix. Open Reviewer Portal is disabled when no approved portal origin is bundled. An independent reviewer reviews through that portal; collectors cannot approve their own artifact.

Qualification still required: signed-release browser callback and Keychain prompts; real Cognito refresh, membership revocation, idempotent enrollment and revoked-key rejection; assessment paging and scope changes against the deployed tenant; keyboard/VoiceOver UI review. No live AWS or customer data was used in unit tests.

## Configure and verify without deployment

1. Obtain the approved existing tenant outputs from its release owner. Map the tenant ID to `tenantId`, the exact HTTPS API origin to `apiOrigin`, the separate `webOrigin` to optional `portalOrigin`, the Cognito issuer to `issuer`, its public native client ID to `clientId`, and its hosted UI `/oauth2/authorize` and `/oauth2/token` endpoints to the corresponding fields. `displayName` is the customer-facing label. Do not use a browser client ID, developer preview hostname, client secret, or AWS access key.
2. Add one dictionary with those public strings to `ScopeproofAWSHostedTenants` in `macos/ScopeproofCapture/Resources/Info.plist`. Preserve the other release identity fields. The existing `Scripts/configure_macos_release_identity.sh` configures the independently reviewed hosted API allowlist and signed-update identity; it does not infer AWS tenant settings. Review all public metadata before signing. Validate the plist with `plutil -lint macos/ScopeproofCapture/Resources/Info.plist`.
3. The native Cognito app client must be public with PKCE authorization-code flow, allow `scopeproof-capture://oauth/callback`, and grant `openid`, `profile`, `email`, and `scopeproof/evidence.collect`. The API must resolve its request hostname to the same tenant and return that API hostname as `tenantHostname`; the web hostname is not substituted for it.
4. From the native package directory, run `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --arch arm64` and `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift build -c release --arch arm64`. Use owned temporary module caches and `--scratch-path` where the sandbox requires them. These commands compile/test only; they neither deploy AWS nor sign/notarize/publish the app.
5. For release qualification, use the repository's existing macOS release procedure: approved clean immutable source commit, configured public release identity, `Scripts/prepare_macos_release_candidate.sh`, then the separately authorized signing/notarization process. Do not bypass its clean-worktree/approved-commit checks merely to try onboarding. A source `swift build` is not a qualified distributable app.
6. On a non-production customer tenant, exercise sign-in → verify this Mac → select active assessment/control/system → capture and local review → Submit / Check Capture → observe authoritative quarantine/validation/review state → independent review in the approved web portal → refresh native status. Also cancel during PUT and confirm a subsequent check does not send a second PUT. Record actual scan/review outcomes before claiming a qualified end-to-end deployment.

Transfer Recovery in the Capture menu covers explicit per-item legacy hosted and direct-S3 retry/cancel, with destination snapshots, revalidation, per-attempt credential refresh, and separately displayed verified outcomes. Jira recovery opens the intended issue for manual attachment reconciliation and never automatically discloses another attachment set. AWS runtime submission/status remains in AWS Customer Workspace because its quarantine/scan/review states are not equivalent to a legacy transfer receipt.

For cross-runtime proof interoperability, set `SCOPEPROOF_NATIVE_ENROLLMENT_FIXTURE_PATH` to an owned temporary JSON path during `swift test --filter signsEnrollmentContract`. Then run `node --experimental-strip-types macos/ScopeproofCapture/Scripts/verify-native-enrollment-fixture.mjs REPOSITORY_ROOT FIXTURE.json`. The fixture contains synthetic public proof only and the check invokes the real server verifier, catching signing-domain or canonical-JSON contract drift.
