# Scopeproof Capture for macOS

For a complete new-Mac walkthrough, including DMG and source installation, permissions, capture, review, export, S3, one-time SBOM, Jira, and troubleshooting, start with [the repository getting-started guide](../../docs/GETTING_STARTED.md).

The current source metadata allocates **Unreleased Scopeproof Capture 1.10.0 (build 25)** and postdates the public 1.8.1 preview. No 1.10.0 DMG has been published, and this source version is not proof of the bundle installed or running on a particular Mac. It is a local-first menu-bar application for producing, finding, reviewing, storing, browsing, downloading, and packaging timestamped PCI DSS, HIPAA, FedRAMP, SOC 2, ISO 27001, and custom compliance evidence screenshots, plus one-time repository SBOM exports.

Related guides: [installation and updates](../../docs/MACOS_INSTALLATION.md), [operator workflow](../../docs/OPERATOR_GUIDE.md), [AWS S3 evidence storage](../../docs/S3_STORAGE.md), [Jira handoff](../../docs/JIRA_HANDOFF.md), [repository SBOM generation](../../docs/SBOM_GUIDE.md), [assessor verification](../../docs/ASSESSOR_GUIDE.md), and [security model](../../docs/SECURITY.md).

## Build and run locally

Requirements: macOS 14 or newer and Apple’s Swift toolchain. From the repository root, run:

```bash
./Scripts/run_macos_capture.sh
```

This single command builds the app, installs it in `~/Applications`, and launches it without requiring an administrator password. Both build publication and installation use fresh staged bundles, verify them before use, replace by same-volume rename, and restore the prior complete app on replacement failure; stale resources are never merge-copied into a new bundle. The installer stops a running Scopeproof process even with `--no-launch`. This path requires the repository and Swift toolchain; the downloadable DMG does not. Scopeproof opens a private Local Console in the browser automatically. No hosted login or enrollment token is required for local workflows. Look for the shield in the menu bar to capture evidence or reopen the console.

The checked-in `Info.plist` contains no allowed hosted API origin. This normal release-mode source build is therefore intentionally local-only for HTTPS hosted synchronization and cannot be redirected by typing an arbitrary server URL. A reviewed production candidate must set one exact pathless `SCOPEPROOF_HOSTED_API_ORIGIN` through `Scripts/configure_macos_release_identity.sh` before building; development-only debug builds may use loopback HTTP for integration testing.

Choose **Generate Repository SBOM…** from the shield menu for a direct one-time CycloneDX 1.6 or SPDX 2.3 export. The native app accepts an exact GitHub URL, a short-lived repository-scoped token, and a branch/tag/commit; reads only recognized lockfile blobs through GitHub's API; saves JSON plus a SHA-256 checksum; and does not persist or retry the credential. Use the hosted workflow instead when the SBOM must be assessment-scoped, independently approved, compared with a prior run, or included automatically in a Scopeproof assessor package.

## Local Console

The embedded console provides overview metrics and one organized screenshot library for the active tenant/workspace across local storage and the matching verified S3 prefix. It supports search plus framework, control, assessment-period, lifecycle, and storage filters; and groups cards by control, period, framework, or no grouping. A `Local + S3` label requires the local upload receipt to match the tenant/workspace, exact image/manifest keys, versions, ETags, S3 checksums, destination, and local digests. S3-only inventory is explicitly provenance-unverified and cannot be reviewed as valid evidence. Its opt-in preview fetches the paired exact-version manifest before the PNG, verifies their identity and SHA-256 relationship, serves bytes only to the authenticated loopback session, and removes the private temporary files. **S3 files…** opens the native exact-version download browser.

The console binds only to `127.0.0.1`, exchanges a one-time URL-fragment nonce for a rotated in-memory bearer, creates no localhost authentication cookie, and stops when Scopeproof quits. Browser requests carry the bearer and identify artifacts only by evidence ID; no filesystem path, S3 object key, or AWS credential enters the browser API. Switching tenant/workspace stops the old console and invalidates its session. Without a configured and verified S3 destination, or when its temporary session is unavailable, the library continues in local-only mode and explains how to recover.

Scopeproof maintains a rebuildable SQLite search index under the current user's Application Support folder. Immutable PNG manifests and `.review.json` lifecycle records remain authoritative. A separate append-only SQLite audit chain is HMAC-authenticated with a device-only Keychain key. Hosted synchronization and Jira Cloud remain optional; local capture, review, search, retention, and package export do not depend on a hosted scanner or timestamp authority.

When you make the first capture, allow **Scopeproof Capture** under **System Settings → Privacy & Security → Screen & System Audio Recording**. Quit and reopen the app once after granting access. If Swift is unavailable, run `xcode-select --install`, finish the installation, and retry the command.

## Capture workflow

1. Launch the app and select the shield icon in the macOS menu bar.
2. Choose an exact browser window, capture the frontmost browser, combine a scrolling evidence page, open a URL after a delay, or capture a full display.
3. In the pre-capture dialog, select a compliance framework and corresponding control, customize the filename, and confirm the owner, optional Jira issue, tags, expected evidence, and prefilled context. The **Catalog** row shows the selected version, source, and control count. Use **Update Controls…** to import a current, approved Scopeproof JSON, OSCAL JSON, or CSV catalog; imports are bounded, normalized, duplicate-checked, and recorded with a SHA-256 digest. Use **Capture Presets** for recurring collections.
   **Capture Frontmost Browser Window** prefills the complete active-tab URL for Safari, Chrome, Edge, and Arc when macOS browser Automation access is allowed. Confirm it before capture. Detection failure leaves the URL empty for safe manual entry; Firefox always uses manual entry.
4. Scopeproof runs local OCR and masks detected PANs and credentials. In the review workspace, drag over any additional sensitive value before saving. The unredacted capture is never retained.
5. Find the stamped PNG, immutable current capture manifest, and hash-chained review record under `~/Documents/Scopeproof Evidence/<Compliance area>/<Control>/<Assessment period>` for `local/default`, or under `~/Documents/Scopeproof Evidence/tenants/<tenant>/workspaces/<workspace>/…` for a named identity. Configure that identity before capture, enrollment, or S3 verification. The manifest is signed with a device-only P-256 provenance key and advances a tenant-scoped local chain. A Keychain journal recovers a complete save or removes a partial save after interruption. Captures created by earlier versions under `~/Pictures/Scopeproof Evidence` remain discoverable and are not moved automatically.

Unsigned schema-6 and older artifacts are exposed only through a visibly unverified legacy browsing/migration path. They cannot acquire new trusted review, legal-hold, retention, upload, package, or Jira state. Recapture them with the current app instead of rewriting their manifests or grandfathering them by status.

### Scrolling evidence

Choose **Capture Scrolling Evidence…** when one browser viewport cannot show all evidence for a control. Select the browser window and Scopeproof captures its current view. Switch back to the browser, scroll down with a small visible overlap, return to Scopeproof, and choose **Capture Next Section**. After two or more sections, choose **Finish & Review**. Keep the window size and browser zoom unchanged throughout the sequence.

Scopeproof creates one vertically combined PNG with a numbered divider before each continuation viewport and one evidence banner containing the timestamp, control, and source origin. It caps the number and dimensions of sections so the final PNG remains acceptable to the local and hosted validation pipeline. Intermediate viewports remain in memory and are discarded on cancel or failure; only the reviewed, redacted, exact-scanned composite is saved.

## AWS S3 storage

Choose **AWS S3 Storage…** and use **Production compliance** with **IAM Identity Center profile** or **Identity Center + assumed role**. Set the active tenant/workspace first. Scopeproof can start the AWS CLI v2 browser login, retrieves only expiring STS credentials, keeps those credentials in memory, refreshes them when necessary, and verifies that every refreshed identity still matches the bound AWS account, role, tenant, and workspace. Manual STS entry remains available for break-glass use. Enter a nonempty base prefix, customer-managed KMS key, COMPLIANCE Object Lock retention, optional Deep Archive/replication, and FIPS endpoints. Governance is visibly labeled non-production and cannot be selected with Production compliance. **Save & Verify** binds the KMS ARN to the STS-verified bucket-owner account, partition, Region, tenant, and workspace; calls `kms:DescribeKey`; requires an enabled customer-managed symmetric encryption key; checks the SSE-KMS Bucket Key when applicable; and verifies the complete exact bucket posture including deletion denies. **Create & Harden Bucket** performs the same key preflight before configuration and re-verifies it after an irreversible-retention confirmation. Only manually entered credentials use the device-only Keychain; the verified destination/KMS binding always does. **Browse S3 Evidence…** lists up to 5,000 immutable versions and downloads only a selected PNG/JSON version after ETag, size, checksum, and content validation. **Upload Pending Evidence to S3** retries any capture without a local S3 receipt.

Select SSE-KMS or DSSE-KMS when entering a customer-managed key; SSE-S3 does not use a KMS ARN. Compatible S3 may use a dedicated bucket/prefix-scoped no-console IAM user as a temporary migration exception. Production compliance requires an expiring STS session. Direct Identity Center profiles are supported; static-key, `credential_process`, web-identity, chained source, and arbitrary CLI configurations fail closed. The S3 guide includes IAM/KMS policies and optional CloudFormation authentication templates.

Remote objects are organized as `<prefix>/tenants/<tenant>/workspaces/<workspace>/<control-id>-<control-title>/<assessment-period>/<evidence-id>/` and contain the exact verified PNG plus its immutable JSON manifest. Each SigV4 PUT includes SHA-256, expected-owner, and selected KMS headers; the local receipt records exact S3 version IDs, returned checksums, encryption, retention, identity, account/principal, and request IDs. Before local expiry relies on S3, Scopeproof verifies every exact version, ETag, checksum, KMS setting, and future COMPLIANCE retention live; a receipt alone cannot authorize cleanup. See the [S3 storage guide](../../docs/S3_STORAGE.md) for separated IAM policies, CloudTrail monitoring, and recovery testing.

Every browser screenshot receives a live right-side Mac menu-bar pixel strip across the top, followed by a full-width, high-contrast evidence header and the captured browser pixels. The live strip includes the system-displayed date/time and status context; full-display mode includes the real menu bar directly. The evidence header contains local date, time, timezone, compliance framework, control number/title, optional Jira issue, system, source window, source origin, and a unique evidence ID. Enter or confirm the Page URL in the capture dialog; **Open URL & Capture** supplies it automatically. Before evidence is rendered or persisted, Scopeproof reduces the value to its lowercase HTTP(S) origin and removes user information, path, query, and fragment. The menu bar, header, and source image all pass through OCR, automatic redaction, manual review, and the exact final-PNG scan. Filenames include the framework, control, optional Jira issue, custom evidence name, capture time, and evidence ID. The adjacent JSON manifest contains UTC time, classification metadata, Jira reference, origin-only source metadata, final pixel dimensions, redaction counts, capture method, timestamp context, the PNG SHA-256 digest, and the previous/current chain hashes. A successful production hosted upload adds a local receipt containing the server-signed attestation and the required verified RFC 3161 timestamp token.

Use **Search Evidence…** in the shield menu to filter screenshots by framework, control, review status, age, and system; search their filename, Jira issue, title, owner, tags, notes, or evidence ID; inspect thumbnails; and open or reveal a result. **Review Status…** moves an artifact through Draft, In Review, Approved, Rejected, and Superseded while preserving each decision in a signed, hash-chained `.review.json` sidecar. Approval, rejection, supersession, and local legal-hold changes require a rationale and macOS local-user authentication. Lifecycle and hold use separate tenant/workspace/file-scoped Keychain rollback heads and signing domains.

Use **Export Assessor Package…** after review. The exporter includes only Approved evidence in the chosen framework/period scope, revalidates every screenshot hash and review chain, and creates a ZIP organized by framework and control. Each package contains a Read Me, control-coverage/gap CSV, evidence index CSV with Jira references, optional Jira handoff guide, signed JSON manifest, verification guide, PNGs, capture manifests, lifecycle records, and available server receipts. A separate SHA-256 checksum file is written beside the ZIP.

## Jira handoff

1. In the Scopeproof web console, open **Connections → Jira Cloud**, enter the Jira Cloud site and allowed project keys, then authorize the site through Atlassian OAuth and test the connection. OAuth tokens remain encrypted on the hosted server and never enter the Mac app.
2. Open **Capture & Jira Settings…** on the Mac and enter the Jira HTTPS site, default project key, preferred attachment set, and any internal handling steps. These are handoff defaults, not credentials.
3. Enter a destination key such as `GRC-123` during capture. It becomes part of the banner, filename, immutable manifest, Search Evidence result, hosted metadata, and package index.
4. Review and approve the artifact locally, upload the exact schema-8 PNG/manifest pair to Scopeproof, and wait for the independent server scan, trusted RFC 3161 timestamp, and final device-chain linkage. The signed tenant/workspace pair must exactly match the isolated hosted deployment. Only then can an authenticated web reviewer read and approve the hosted artifact. In **Search Evidence…**, choose **Upload to Jira Cloud…**, inspect the live issue summary, and explicitly confirm the upload. Scopeproof verifies both approvals, the exact PNG and manifest hashes, server safety record, signed attestation, finalized provenance, site, project allowlist, and Jira permissions before attaching the evidence set.
5. Keep the signed `.jira.json` receipt beside the evidence. **Copy Jira Comment** and manual attachment remain available as a fallback. Confirm project permissions, external-auditor access, data classification, and retention first.

The app never captures on a timer or in the background without an explicit menu action. Local OCR runs on the Mac and recognized text is not retained. The hosted service independently runs OCR/DLP over the exact uploaded PNG and likewise retains no recognized text—only digest-bound policy, scanner-origin, completion, and receipt metadata. Device credentials and provenance private keys are stored in separate device-only macOS Keychain items, not preferences or screenshot metadata.

## Optional hosted synchronization

1. In the web app, open **Connections → Mac capture devices → Enroll device**.
2. Copy the one-time token immediately; only its hash is retained by the server.
3. Confirm the app release was built with that exact pathless HTTPS origin in `ScopeproofHostedAPIOrigins`. The checked-in source array is empty; the release operator supplies `SCOPEPROOF_HOSTED_API_ORIGIN` through `Scripts/configure_macos_release_identity.sh`. In the menu-bar app, open **Capture & Jira Settings**, enter the same Scopeproof origin, paste the token, and optionally enable automatic upload.
4. Use **Retry Pending Uploads** after an offline capture. Tokens can be revoked from the web app at any time.

The enrollment token authenticates the API request and HMAC-binds the exact manifest/PNG digests. Separately, the app signs the canonical schema-8 manifest—including the exact customer and workspace identifiers—with its device-only P-256 provenance key and supplies a contiguous local chain sequence. The hosted API requires those identifiers to match `LEGACY_TENANT_ID` and `LEGACY_WORKSPACE_ID`, rejects unsigned, rebound, mismatched, ambiguous, malformed, oversized, non-current, or polyglot uploads, and derives metadata only from that signed manifest.

Before storage, the server independently scans the exact PNG bytes through the service configured by `BROWSER_OCR_ENDPOINT`, `BROWSER_OCR_TOKEN`, and `BROWSER_OCR_ALLOWED_HOSTS`. Those legacy names cover native screenshots as well as browser-originated evidence. It then obtains and verifies the required RFC 3161 timestamp, reserves the exact next device-chain link, encrypts/stores the artifact, and finalizes the artifact ID, image/manifest digests, event hash, sequence, and provenance-key link. Production readiness fails when the independent scanner is missing/unsafe, when trusted timestamp enforcement is disabled, or when timestamp trust material is incomplete.

A scanner or required-timestamp failure stores no hosted artifact and leaves the local evidence usable. A failure after storage but before final chain linkage leaves the hosted record quarantined: read/preview, approval, package/export, and Jira disclosure all remain blocked until the original exact current pair is retried and reconciled. Existing unbound records must be re-uploaded and rescanned; unsigned legacy material must be recaptured. Never grandfather either case with a direct database update. Hosted operators must apply migrations through `0028_native_reconciliation_cursor.sql`. No AWS infrastructure is deployed by building or running this Mac package.

## Build only

From the repository root:

```bash
./Scripts/build_macos_capture.sh
```

The signed local app is created at `DerivedData/Scopeproof Capture.app`, but it is not installed or launched. The builder stages and verifies a fresh complete bundle, then replaces the prior output atomically on the same volume with rollback on failure. Use `./Scripts/run_macos_capture.sh` for the one-command local workflow.

The local build uses an explicit designated requirement tied to `com.scopeproof.capture`. This keeps the app's Screen Recording permission identity stable across local rebuilds.

For a production release, provision the offline update public key and validity window under `ScopeproofUpdatePublicKeys`, one exact HTTPS `ScopeproofUpdateDownloadOrigin`, and one exact HTTPS `ScopeproofHostedAPIOrigins` entry under `Info.plist`, then create the signed/notarized candidate with the protected production workflow. `Scripts/configure_macos_release_identity.sh` requires both `SCOPEPROOF_RELEASE_DOWNLOAD_ORIGIN` and `SCOPEPROOF_HOSTED_API_ORIGIN` and validates that each is a pathless HTTPS origin. Download the candidate's exact attested seven-file artifact set and pass its directory, repository, approved commit, update key, version, sequence, exact versioned URL, team, and designated requirement to `./Scripts/publish_release.sh`. The script snapshots and verifies rather than rebuilds the candidate and signs an update envelope over the exact ZIP. Configure that envelope through `MACOS_RELEASE_MANIFEST_JSON`, `MACOS_RELEASE_SIGNATURE_DER_BASE64`, and an exact `MACOS_RELEASE_ALLOWED_HOSTS` value. The app derives `/macos/<version>/Scopeproof-Capture-<version>.zip` from its compiled origin instead of following a manifest-selected host or redirect, verifies the downloaded bundle ID/version, and stores the last accepted `(sequence, version, SHA-256)` tuple in a device-only Keychain item. It rejects rollback, same-sequence equivocation, wrong keys/digests/teams/requirements, Gatekeeper failures, and releases without a valid stapled notarization ticket.
